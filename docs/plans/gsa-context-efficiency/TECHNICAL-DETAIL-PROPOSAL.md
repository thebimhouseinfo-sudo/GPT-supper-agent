# GSA1–GSA4 — Technical Detail Proposal (Pre-Code, Revised Architecture)

## GOAL

Define the **best defensible functional grouping** of existing GSA source in the Technical Proposal and **review it against real source dependencies before changing code**. `index.ts` should be the concise application entrypoint / navigation map: initialize dependencies, register functions/tools/routes and expose the MCP server, not contain every domain's business logic. Group what is normally **read, reasoned about, changed and tested together**; neither one-function-one-file fragmentation nor a new set of giant mixed files is acceptable.

**GSA1 = REQUIRED, behavior-preserving modularization foundation**, even if measured context/time is initially worse. `GSA2` = harness-content optimization; `GSA3` = tool/skill-result optimization; `GSA4` = proven role/task/phase-scoped loading. Revisit/merge/split GSA1 module boundaries in later candidates **only on evidence**, not because modularity alone guarantees a speedup. The practical effect is measured by actual code-navigation/edit workloads; no claim of exact ChatGPT token accounting.

## A. Verified current code structure and why previous proposal was insufficient

Actual source inspection on the pinned runtime:
- `index.ts` includes `createServer(req)` at ~3446, 55 `server.registerTool` calls (~3492–8769), and HTTP `/selftest`, `/health`, `/mcp` routes ending at `Deno.serve(root.fetch)`. The file is the only TypeScript file under `gsa-mcp/` at the current revision.
- Domain helpers coexist in the same file: bootstrap/Advisor `projectBootstrapChecklistDecision`, `projectBootstrapReadinessDecision`, `projectCriteriaAdvisoryDecision` (~1112–1450); plan/topology `validateNextPlanningModel`, `milestoneLoopDecision` (~1450–1698); plan supersession `assessHumanPlanChangeJobs`, `prepareHumanPlanChangeIntent`, `resumeHumanPlanChangeIntent` (~1700–2110); cursor/recovery/orchestration ~2111–2462; model-facing harness/skills `BASE_AGENT_HARNESS`, `ROLE_HARNESSES`, `ROLE_SKILLS`, `ROLE_HOST_SKILLS`, `RUNTIME_SKILLS`, `renderHarness` (~2474–3075); project manifest/authorization helpers ~3076–3446.
- Public tool registrations are **interleaved**, not grouped by responsibility: Project handlers ~5200–6074; plan-change ~3576–3711; agent skill tools ~6122–6214; job/review ~6215–7295; run/checkpoint ~7296–8684. Reorganizing only top-level constants leaves a large `createServer` and repeated source-navigation cost.
- The `/selftest` inline Hono callback occupies approximately **lines 8802–9733 (~932 lines)** and directly exercises numerous Project, Plan, Execution and evidence helpers. Keeping it inline defeats the thin-entrypoint goal even after moving tool handlers. It is a coherent diagnostics boundary, but moving it requires exact call/import mapping and cannot silently alter the selftest oracle.
- `get_skill_catalog` **already** returns name/description, `load_skill` returns body; `renderHarness(role)` **already** scopes to a Role. GSA3/GSA4 must not relabel existing capabilities as savings.
- Several `test-lab/*.test.cjs` tests directly AST-extract functions/constants/tool callbacks from `index.ts` (e.g. `runtime-logic`, `planner-critical-challenge`, `llc59-autonomy-harness`, `stopchat-handoff`, `scenario-tester-integration`). A module move breaks their source-discovery assumptions even when functionality is unchanged; tests must follow actual modules, preserving original assertions.
- CI uses exact paths `.github/workflows/gsa-next-logic.yml`; module paths must enter trigger filters and `deno check` must cover the real entrypoint dependency graph. Public auth/OAuth, route exposure, schema, text-fallback, durable GitHub steps, external branch/Job writes and state transitions MUST remain identical under GSA1.

**Review hypothesis, not established outcome:** Smaller cohesive modules should reduce GSA Coder's source-navigation reads/repeated search, but may increase import chasing. Static proposal review can judge call-graph fit and correctness risks; only actual matched development work proves efficiency. `index.ts` as a thin composition root should be an outcome, not a reason to create excessive adapters/registries.
